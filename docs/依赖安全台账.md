## 环境备注

- npm registry 指向 `registry.npmmirror.com`，其 audit 端点未实现（`npm audit` 本地不可用），
  GitHub 侧 Dependabot 是唯一信号源。tarball 安装不受影响。
- 本机到 `api.github.com` 的 HTTPS 链路不稳定（SOCKS 代理抖动，`git push` 走 SSH 正常）。
  拉取告警若超时，给 `gh` 显式走代理再试：`HTTPS_PROXY=socks5h://127.0.0.1:1082 gh api ...`
- 根 `package-lock.json` 与 `windows/package-lock.json` 均使用 lockfileVersion 3。
- **`~/.ssh/config` 里 github.com 走 `ProxyCommand nc -x 127.0.0.1:1082`，该 SOCKS 代理
  经常不在监听**，症状是 `git push` 报 `Connection closed by UNKNOWN port 65535`。
  本机到 ssh.github.com:443 与 github.com:22 均可直连，代理挂了不必修代理，
  用一次性配置绕过即可（不要改 `~/.ssh/config`，用户平时是要用代理的）：

### 那这个文件到底有什么用

`dependabot.yml` 开的是 **version updates**（周期性保鲜），与 security updates 是
两条独立通道。实际价值不是"开始有自动化"，而是：

- **让安全 PR 更容易落地**。官方排错文档写明：security update 因超时/冲突失败时，
  缓解办法是「保持依赖常新，例如启用 version updates」。依赖越陈旧，自动修复越容易
  撞冲突然后失败——这才是本项目真正的痛点。
- 把「等上游发版」变成「上游一发版就有 PR」，而不是靠人隔几天重扫。

三个配置决定都有文档依据，不是照抄模板：

| 决定 | 依据 |
|---|---|
| **不设 `target-branch`** | 一旦设置，本节配置与 security updates **解耦**，只作用于 version updates。不设才能让 labels / commit-message 同样作用到安全 PR |
| **`ignore` 只写 `update-types`，绝不写 `versions`** | 官方文档 + GitHub 工程师在 github/docs#24966 明确：`ignore.versions` **会连 security updates 一起压掉**；`ignore.update-types` 单独用时**只影响 version updates**。所以屏蔽 major 用 `update-types: [version-update:semver-major]`，需要跨 major 的安全修复照样出 PR |
| **不靠 `open-pull-requests-limit` 降噪** | 该选项对 security updates **无效**（安全 PR 另有内部上限 10），设 0 只会关掉 version updates |

另外 `commit-message` **没有加 `include: "scope"`**：它会把 `(deps)`/`(deps-dev)`
追加到 prefix 之后，与本已含 `(deps)` 的 `fix(deps)` 叠成 `fix(deps)(deps)`。
