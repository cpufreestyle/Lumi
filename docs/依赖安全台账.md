## 关键结论：唯一该优先修的是 proxy-addr

22 条里 **21 条在 `windows/` 的 Electron 依赖树**（本地开发/打包 Windows 端才触及），
而 **proxy-addr 那条 critical 在根 `package.json` 的生产依赖树里**——`express` 传递依赖它，
是随 `npm start` 上线的那份。它也是全表唯一「补丁级升级即可修复」的：2.0.7 → 2.0.8。

```bash
# 修复方式：在根 package.json 增加 override（既有 qs override 同款写法）
"overrides": { "proxy-addr": "^2.0.8" }
```

风险低：proxy-addr 2.x 内补丁升级，API 无变化；但升级后需回归一次 `npm test`
（41 条 Node 测试覆盖 express 路由与激活码换发，能兜住破坏性变更）。

其余 21 条的复评触发条件维持原判断：都在 Windows 端 Electron 树，
计划做 Windows 发版或 Electron 主版本升级时一并评估；其中 vite 5→6、esbuild 0.21→0.25
需单独验证 `npm run build:win`，不可与其它改动混在一次提交里。

## 维护纪律

每次推送后 GitHub 返回的漏洞计数若与本表「当前总数」不一致，以 GitHub 为准并更新本表。
核对命令（改计数就必跑，别靠记忆）：

```bash
gh api 'repos/cpufreestyle/Lumi/dependabot/alerts?per_page=100&state=open' \
  --jq 'group_by(.dependency.package.name)
         | map({pkg:.[0].dependency.package.name, n:length,
                sev:(map(.security_advisory.severity)|unique|join(",")),
                fix:(map(.security_vulnerability.first_patched_version.identifier // "—")|unique|join(","))})
         | sort_by(-.n) | .[] | "\(.n)\t\(.pkg)\t\(.sev)\tfix=\(.fix)"'
```

本台账不替代 CI 自动化；若启用 `.github/dependabot.yml`，应在 PR 模板里引用此文档
以避免重复 triage。
