# 交接：动态岛展开面板排版（2026-09-27）

> 相关文档：封面错图修复见 `handoff-封面错图修复-2026-09-27.md`。
> 本篇只覆盖**展开面板标签栏的排版**，不涉及封面/歌词链路。

## 一句话

标签栏下方的大片空白与左侧那条孤立竖线，都是布局写法问题而非间距问题；
已改为「两个独立网格上下排 + 滚动区贴合内容高度」，并整体收紧间距。

## 现象

用户截图反馈三点：

1. 标签栏下方一大片黑色空白，模块内容（音乐面板等）不显示。
2. 标签区左边有一段**孤立的竖线**，与任何标签都不挨着。
3. 整体排版偏松散，要求「放两行、紧凑点」。

## 根因

### 1. `ScrollView(.vertical)` 垂直方向贪婪 —— 空白的主因

`IslandViews.swift` 的 `TabBarView` 用了 `ScrollView(.vertical, showsIndicators: false)`
包标签网格。SwiftUI 里 `ScrollView` 在其滚动轴上是贪婪的：它会吃掉父容器给它的
全部高度。`ExpandedView` 的结构是：

```
VStack(spacing: 0) {
    TabBarView()                        // ← 其中含贪婪 ScrollView
    moduleContentView.frame(maxHeight: .infinity)   // ← 抢不到高度
    底部拖拽指示器
}
```

`TabBarView` 的 ScrollView 抢走剩余高度 → `moduleContentView` 被压到 0 →
表现为「标签栏下面一整块空白，模块内容不显示」。

> 上一轮把 `ScrollView(.horizontal)` 改成 `.vertical` 时引入的回归：
> 横向 ScrollView 只在水平方向贪婪，垂直方向会贴合内容，所以之前没暴露。

### 2. `groupDivider` 是网格的一个「单元格」—— 孤立竖线的成因

原先用一个 `Rectangle`（宽 0.5pt）作为 `LazyVGrid` 的一个 item 插在
「内置模块」和「插件」两组之间来分组。当 12 个内置标签恰好占满一行时，
这个单元格会被折行挤到**第二行的行首**，渲染成一段谁也不挨着的断线。

### 3. 面板 625×797 不是 bug

`defaults read com.lumi.app island_user_size` → `(625, 797)`。
这是用户拖拽手柄后持久化的尺寸（默认 360×480，游戏模块 480×600，听写 480×520）。
空白消失后这个尺寸可正常装内容。

# 第三轮：固定两行 + 可拖拽行高

## 需求

用户要求：「这里固定就 2 行，或者可以自己拖拽行高」，
随后澄清：「**是所有内容都在两行**」。

两个诉求都做了：

1. **所有内容恒为两行** —— 包括原先独占第三行的三个工具按钮
   （歌词设置 / 隐藏界面 / 退出），现已并入第二行网格尾部。
2. **行高可拖拽调节并持久化**。

## 为什么第一轮的方案不够

第一轮用的是 `LazyVGrid(columns: [.adaptive(minimum: 46/58)])`。
`.adaptive` 会**按可用宽度决定每行放几个**，于是：

- 面板 625pt 宽 → 内置 12 个排 1 行 + 插件 5 个排 1 行 = **2 行**（截图所见）
- 面板缩窄到 360pt → 内置每行约 7 个 → 2 行 + 插件 1 行 = **3 行**

也就是**行数会随面板宽度漂移**。用户拖一下面板手柄，标签区高度就变了。

## 改动

### 1. 锁列数 → 行数恒定

`GridItem(.flexible(), spacing: 1)` 配合显式 `count:`，让每个网格**恰好一行**：

```swift
// IslandViews.swift
private func tabGrid<C: View>(columns: Int, @ViewBuilder content: () -> C) -> some View {
    LazyVGrid(columns: Array(repeating: GridItem(.flexible(), spacing: 1), count: columns),
              spacing: 1) {
        content()
    }
}
```

`.flexible()` 让单元格平分可用宽度，**宽度自适应但列数固定**，于是行数固定。
`tabLabel` 相应从固定 `width` 改成 `.frame(maxWidth: .infinity)`。

`ScrollView` 整个删掉 —— 行数已确定，不会溢出，也就没有滚动区的必要。
（顺带根除了第一轮那个「垂直贪婪吃掉 moduleContentView」的隐患类别。）

### 2. 工具按钮并入第二行（关键：必须计入列数）

原先三个工具按钮是 `HStack + Spacer` 独占的第三行。已删除该 `HStack`
与底部分隔线，改为在第二行网格尾部追加三个 `toolCell`：

```swift
// IslandViews.swift
private var toolCellCount: Int { 3 }

tabGrid(columns: tabColumns(for: 1 + plugins.plugins.filter { $0.panel }.count + toolCellCount)) {
    // 插件市场入口 … 各插件标签 …
    toolCell(icon: "slider.horizontal.3", …) { … }
    toolCell(icon: "eye.slash", …) { … }
    toolCell(icon: "power", …) { … }
}
```

**最容易踩的坑**：工具按钮必须一起算进 `tabColumns(...)`。
只把标签算进去的话，按钮会把第二行挤成两行，标签栏又变三行 —— 而这正是
用户反复强调要避免的。测试里第二行按 **8**（1 市场入口 + 4 插件 + 3 工具）
而不是 5 来断言，就是为了守住这一点。

`toolCell` 与 `tabLabel` 一样用 `.frame(maxWidth: .infinity)` +
`.frame(height: tabRowHeight)`，因此高度对齐；视觉上用圆形底色与文字标签区分。

### 3. 行高可拖拽

- 新增 `AppState.tabRowHeight`（`Core/AppState.swift`）
  - UserDefaults key `lumi_tab_row_height`，默认 **46pt**，范围 **30...76pt**
  - 接入既有的 `scheduleLayoutPersist()` 防抖落盘（拖拽时每帧都变，不能直接写盘）
- 新增 `rowHeightHandle`：标签网格正下方一条 **8pt 高的透明抓取区**，
  上下拖动改行高，悬停显示 `resizeUpDown` 光标 + tooltip 说明。
  视觉上不画任何东西，避免多一条横线破坏紧凑感。
- 位移做 **1:2 映射**（手指 46pt → 行高 23pt），手感更跟手。
- 拖拽开始时记基准行高 `dragStartRowHeight`，全程以它为原点，避免增量累加漂移。


### 4. 两行严格对齐（整齐紧凑）

按「各自单元数定列数」时，第一行 12 格、第二行 8 格，列宽不一致（55pt vs 82pt），上下错位显得散乱。

**统一列数**：
- 两行共用 `sharedTabColumns = max(内置数, 第二行单元数) = 12`。
- 第一行满 12 列；第二行 8 个单元（1 市场入口 + 4 插件 + 3 工具），中间补 `12 - 8 = 4` 个透明 `spacerCell` 占位撑满 12 列。
- 效果：上下两行每个格子严格等宽，第一列对齐第一列、第二列对齐第二列；工具按钮被推到行尾（最右 3 列），与第一行的最后 3 个内置模块垂直对齐。
- 网格间距 `spacing: 1`，两行之间 `VStack(spacing: 1)`，极其紧凑整齐。

### 5. 抽出纯逻辑 `TabBarLayout`（新增文件）

`Sources/Lumi/Core/TabBarLayout.swift`，只有 Foundation，不引 GUI。

**为什么必须抽出来**：「标签栏恒为两行」是用户硬要求，但把它改回
`.adaptive` 时**编译不报错、运行也不崩，只是行数悄悄变成 3** ——
这类回归只有断言能守住。核心规则是：

| 规则 | 说明 |
|---|---|
| `maxColumns = 12` | 单组标签最多 12 列，超出才允许折行 |
| `columns(forItemCount:)` | 列数 = 标签数（上限 12），即「几个标签排一行」 |
| `rows(itemCount:columns:)` | 向上取整 |
| `totalRows(builtIn:plugin:)` | 两组行数之和 |

> `maxColumns` 是刻意留的后门：插件装到 13 个以上时会变成 3 行。
> 理由是**可读性优先于死守两行** —— 硬塞两行会让每列只剩十几 pt，文字没法看。
> 当前 12 内置 + 5 插件 = 17 个标签，两行绰绰有余。
