## 二、候选方案对比

| 方案 | 速度 | 新增权限 | 冲突风险 | 实现成本 |
|---|---|---|---|---|
| **A. 全局快捷键** | ⭐⭐⭐ 一键，任意 app 前台生效 | 无（复用辅助功能） | 需避开系统/第三方占用键位 | 中 |
| **B. 胶囊右键/中键** | ⭐⭐ 需先把鼠标移到刘海唤出胶囊 | 无 | 无（左键位已占，右键空闲） | 低 |
| **C. 菜单栏菜单项** | ⭐ 两步点击 | 无 | 无 | 最低 |

**结论**：单靠 B/C 都达不到「快速」，**必须以 A 为主**；B 作为鼠标流的补充，C 承担可发现性与状态展示。

## 三、推荐设计

### 3.1 主路径：全局快捷键（方案 A）

- 用 `NSEvent.addGlobalMonitorForEvents(matching: .keyDown)` + `addLocalMonitorForEvents` 注册。
- **按 `keyCode` 而非 `characters` 匹配**，避免输入法/键盘布局影响。
- 触发后调用 `MusicController.shared.togglePlayPause()`，并**立即 `fetchInfo()`** 拉一次状态，避免等最长 1.5s 的轮询才刷新 UI。
- 未授予辅助功能时：降级为「仅 Lumi 前台生效」（local monitor 仍可用），并在菜单栏提示去授权。

**默认键位（待你确认）**：候选 `⌥Space`（手感最好，但 Alfred/Raycast 常占用）、`⌘⌥P`（冲突少，P=Play）、`⌃⌥Space`。

### 3.2 补充：胶囊右键/中键（方案 B）

- 用 `NSEvent.addLocalMonitorForEvents(matching: [.rightMouseDown, .otherMouseDown])` 判断落点是否在胶囊窗口内。
- 不改现有左键语义，零冲突。

### 3.3 可发现性：菜单栏（方案 C）

- 菜单加入「播放 / 暂停」项，标题随 `isPlaying` 变化（如「⏸ 暂停」「▶️ 播放」）。
- 快捷键触发时，菜单栏图标短暂切换为 play/pause 符号约 0.8s 作为操作确认。

### 3.4 关键决策：不能违反 hover-only

你此前明确要求「**鼠标没碰到刘海时不要出现胶囊**」。因此：

- 快捷键触发**不强制弹出胶囊**（否则直接违背该规则）。
- 反馈改走「菜单栏图标短暂变化」——既有确认感，又不破坏既定交互。

### 3.5 Music 未运行时的行为

- 用户**显式**触发播放，启动 Music 是符合预期的（对应「快速启动播歌」）。
- 建议默认允许启动，并在设置中提供开关「Music 未运行时不启动」，避免误触唤起。

## 四、实施分期

**第一期（主）**
1. 新建全局快捷键模块（注册/注销/键位持久化）
2. 接入 `togglePlayPause()` + 触发后立即 `fetchInfo()`
3. 菜单栏「播放/暂停」项 + 状态显示
4. 设置弹层中加入键位配置（复用 `LyricTuningPanel` 模式）

**第二期（补充）**
5. 胶囊右键/中键切换
6. 权限缺失时的降级与引导

## 五、验收标准

- [ ] 任意 app 前台按下快捷键 → Music 播放/暂停切换，响应 < 300ms
- [ ] 触发后胶囊状态（歌词/歌曲信息）在 0.5s 内同步，不等轮询
- [ ] **快捷键不会在鼠标未触碰刘海时弹出胶囊**
- [ ] 未授予辅助功能时降级为 Lumi 前台可用，且有明确提示
- [ ] 键位可在设置中修改并持久化（UserDefaults）
- [ ] 菜单栏显示当前播放状态，点击可切换
- [ ] 编译 0 error / 0 warning，`preview_restart.sh` 重启验证通过
